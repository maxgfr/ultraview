# ultraview — technical spec (v1)

> See your app instead of reading its code. The visual layer over ultraindex:
> codeindex says where things are, ultraindex says what they mean (and proves
> it), ultraview shows it — to the business and to developers — and lets you
> ask, save the answer as a view, and follow every change your agent makes.

Related: the agent's side is [skills/ultraview/SKILL.md](../skills/ultraview/SKILL.md)
and its [references](../skills/ultraview/references/); extractor coverage and
gaps are in [src/extract/README.md](../src/extract/README.md), real-repo
measurements in [tests/corpus.md](../tests/corpus.md), the offline evals in
[evals/README.md](../evals/README.md); the product overview and the comparison
with other tools in the [README](../README.md).

## 0. Ground rules

- Deterministic work belongs to code, never to the model: graph, symbols,
  routes, entities, diffs, insights, layout. The model writes only meaning:
  names, summaries, capabilities, flows, lens answers — and every sentence it
  writes cites `[path:line]`, checked mechanically.
- One engine copy: ultraview vendors **ultraindex's library**
  (`src/vendor/ultraindex-engine.mjs` + `.d.mts`, via `webindex skill vendor`,
  pinned in `skill.json`), which re-exports the pinned codeindex as the
  `codeindex` namespace. No second codeindex copy. No module under `src/` may
  declare a name the engine already exports (`webindex skill check`).
- Extractors missing from codeindex live in `src/extract/` as pure functions
  over `(rel path, text, FileRecord)` with no I/O and no model, so they can be
  upstreamed to codeindex unchanged.
- Zero runtime dependencies; one tsup bundle `scripts/ultraview.mjs` mirrored
  into `skills/ultraview/scripts/`; the viewer is one self-contained offline
  HTML (`skills/ultraview/assets/viewer.html`) produced by esbuild with JS/CSS
  inlined.
- Byte-stable outputs: sorted keys and arrays, `\n` line endings, trailing
  newline, no timestamps in generated files except where named (`at`).
- English everywhere in the repo. Viewer UI strings through i18n
  (`viewer/i18n/en.json` source + fallback, `fr.json`).

## 1. On-disk layout (in the analyzed repo)

```
.ultraindex/                 # owned by ultraindex (graph, symbols, encyclopedia, manifest)
.ultraview/
  model.json                 # AGENT-AUTHORED, committed: app, systems, capabilities, edges, tour, glossary
  flows/<id>.json            # AGENT-AUTHORED, committed
  lenses/<id>.json           # AGENT-AUTHORED, committed (one saved question = one view)
  timeline.jsonl             # APPENDED, committed: one line per agent task / PR / manual note
  changes/<id>.json          # GENERATED by `diff --record`, committed (history of change views)
  facts.json                 # GENERATED (extractors), gitignored
  view.json                  # GENERATED (merged view-model), gitignored
  index.html                 # GENERATED, gitignored
  hook.log                   # WRITTEN by the Stop hook on error only, gitignored
  ask.log                    # GENERATED by `serve --ask` (agent output), gitignored
  .gitignore                 # written by `build`: facts.json, view.json, index.html, hook.log, ask.log
```

`ultraview build` writes `.ultraview/.gitignore` itself so the committed part is
exactly the meaning + history, never regenerable data. Nothing committed holds
a machine-local path: `repo.root` lives only in the gitignored view.json.
Outside `.ultraview/`, only `hook install` writes, and only into
`<repo>/.claude/settings.local.json` (personal, not committed; or the shared
`.claude/settings.json` with `--shared`), when asked.

## 2. Node identity

Every node has a namespaced id, stable across runs:

| prefix | example | source |
|---|---|---|
| `cap:` | `cap:checkout` | model.json capabilities |
| `sys:` | `sys:web` | model.json systems (else derived from workspaces) |
| `mod:` | `mod:src-payments`, `mod:src@database` | ultraindex module slug (`@<sys>`: a slice, below) |
| `file:` | `file:src/pay/stripe.ts` | graph |
| `sym:` | `sym:src/pay/stripe.ts#createCharge` | symbols |
| `route:` | `route:POST /api/checkout`, `route:QUERY user.byId`, `route:ACTION app/actions#save` | facts (HTTP routes; tRPC procedures; Next server actions) |
| `screen:` | `screen:/cart` | facts |
| `entity:` | `entity:Order` | facts |
| `job:` | `job:send-receipts` | facts |
| `ext:` | `ext:stripe` | facts (SDK import / host / env prefix) |

Containment (structural tree): `sys ⊃ mod ⊃ file ⊃ sym`; routes/screens/jobs
hang off the file that defines them; entities off the schema file. A file's
system is decided by one rule, `systemOfFile` (src/model/assemble.ts): the
most specific matching model glob (longest literal prefix, ties by
declaration order, `exclude` honoured), else the deepest workspace package,
else `sys:app`; a file nothing matches sits in `sys:_unassigned`. The tree,
coverage, `show`, `dossier` and `check` all read that one assignment, so a
file always sits in the system its glob declares. A module whose files span
several systems is cut into **slices**, one per system: `mod:<slug>` sits in
the system holding most of its files (ties by declaration order,
`_unassigned` last) and `mod:<slug>@<sys>` in each other one
(`mod:src@database`). Slices share the module's label; a minority slice is
tagged `slice` and carries `slice: { of: "mod:<slug>", system: "sys:<id>",
qualifier: "@ <system label>" }` for the viewer to tell them apart. Each file
hangs under the slice of its own system. Roll-ups (module, system and
capability edges; system metrics) run over slices, so an import from one
system into a file of another shows as an edge between those systems. A
slice's `loc` and `tests` are its own files'; a split module's PageRank is
shared out by its files' PageRank. A capability member `mod:<slug>` claims
every slice of the module, `mod:<slug>@<sys>` that slice only; coverage
counts a module once, claimed when any slice is. Unsplit modules (and, without
a model, modules inside one workspace) are unchanged.
Capabilities are an **overlay**: a capability selects members (systems,
modules, files by glob, routes, entities); one file can serve several
capabilities. Files no capability claims fall into the derived
`cap:_foundations` ("Shared foundations") — never silently dropped.

```json

  "schema": 1,
  "app": { "name": "Shop", "summary": "Online store for … [README.md:3]", "audience": "everyone" },
  "systems": [
    { "id": "web", "label": "Storefront", "kind": "ui", "summary": "… [apps/web/src/main.tsx:1]",
      "paths": ["apps/web/**"], "exclude": [] }
  ],
  "capabilities": [
    { "id": "checkout", "label": "Checkout", "summary": "Turns a cart into a paid order. [apps/api/src/checkout.ts:40]",
      "actors": ["customer"], "members": ["mod:apps-api-src-checkout", "route:POST /api/checkout", "entity:Order"],
      "paths": ["apps/web/src/cart/**"], "tags": [] }
  ],
  "edges": [
    { "from": "sys:api", "to": "ext:stripe", "kind": "http", "label": "charges cards", "cite": "apps/api/src/pay.ts:12" }
  ],
  "tour": [ { "node": "cap:checkout", "note": "Start here: … [apps/api/src/checkout.ts:40]" } ],
  "glossary": [ { "term": "SKU", "meaning": "… [packages/catalog/src/sku.ts:3]" } ]

```

- `kind` ∈ `ui service worker library data external infra script test config`.
- `edges` only for what the engine cannot see (queues, events, webhooks,
  cron, cross-repo); everything detected is derived, never hand-copied.
- `audience` ∈ `everyone developers` (viewer default; user toggles).
- Labels are plain words ("Main server", not "Shop API (Flask)").

```json
{ "schema": 1, "id": "checkout", "title": "What happens when someone pays",
  "trigger": "screen:/cart",
  "steps": [ { "node": "screen:/cart", "note": "Customer clicks Pay. [apps/web/src/cart/Pay.tsx:22]" },
             { "node": "route:POST /api/checkout", "note": "… [apps/api/src/checkout.ts:40]" } ] }
```

```json
{ "schema": 1, "id": "how-refunds-work", "question": "How do refunds work?",
  "answer": "Markdown. Every sentence cites [path:line].",
  "nodes": ["cap:checkout", "route:POST /api/refunds", "entity:Refund"],
  "edges": [ { "from": "route:POST /api/refunds", "to": "ext:stripe" } ],
  "focus": "route:POST /api/refunds",
  "sources": { "<path>": "<sha256 of file at write time>" } }
```

`sources` is filled by `ultraview lens save` / `flow save` (not by the model):
the hashes of every cited file. `check` marks the lens/flow **stale** when any
hash differs (whole-file content hash — a body rewrite behind unchanged
exports is caught). The viewer shows stale items greyed with "re-ask".

## 5. facts.json (generated by extractors)

```json
{ "schema": 2,
  "routes":   [ { "method": "POST", "path": "/api/checkout", "file": "…", "line": 40, "end": 44, "framework": "express", "handler": "checkout" },
                { "method": "QUERY", "path": "user.byId", "file": "…", "line": 12, "framework": "trpc" },
                { "method": "ACTION", "path": "app/actions#save", "file": "…", "line": 4, "framework": "next-action", "handler": "save" } ],
  "calls":    [ { "method": "POST", "url": "/api/checkout", "file": "…", "line": 22, "route": "route:POST /api/checkout" },
                { "method": "MUTATION", "url": "user.update", "file": "…", "line": 9, "route": "route:MUTATION user.update" } ],
  "screens":  [ { "path": "/cart", "file": "…", "line": 1, "framework": "next-app" } ],
  "entities": [ { "name": "Order", "orm": "prisma", "file": "…", "line": 10,
                  "fields": [ { "name": "id", "type": "String" }, { "name": "user", "type": "User", "relation": "User" } ] } ],
  "entityUses": [ { "entity": "Order", "file": "…", "line": 55, "op": "write" } ],
  "jobs":     [ { "id": "send-receipts", "kind": "cron|queue|worker", "schedule": "0 * * * *", "file": "…", "line": 3 } ],
  "externals":[ { "id": "stripe", "via": "sdk|host|env", "file": "…", "line": 1 } ],
  "infra":    [ { "id": "db", "kind": "compose-service|dockerfile|k8s", "file": "…", "line": 4,
                  "overlays": ["env/dev/db.yaml", "env/prod/db.yaml"] } ],
  "links":    [ { "host": "cnil.fr", "file": "…", "line": 31 } ] }
```

Schema 2 (additive over 1, which readers still accept): RPC routes and calls,
`infra[].overlays`, and `links`.

- **RPC routes** share the `route:` namespace with a non-HTTP method: tRPC
  procedures are `QUERY` / `MUTATION` / `SUBSCRIPTION` with the dotted
  procedure path (`route:QUERY user.byId`, routers composed by key across
  files); Next server actions are `ACTION` with the repo path of the module
  without extension and the export (`route:ACTION app/actions#save`). An RPC
  call's `url` is the route path it names, matched by exact method + path.
- **externals `via: host`** only when the URL literal reaches the network: an
  HTTP call site, a client base URL or `url` / `uri` option, a configuration
  default (`process.env.X ?? "https://…"`, `os.getenv("X", "https://…")`), a
  service-named value (`*_HOST`, `*_ENDPOINT`, `*_API*`, `*_DSN` anywhere,
  `*_URL` in a settings module, `apiBaseUrl`), a variable passed to an HTTP
  call of the same file, a CSP `connect-src` / `script-src` / `frame-src`
  source, a known SDK API host (id = the SDK: `api.stripe.com` → `stripe`),
  or the host of an absolute-URL call fact. Reserved and placeholder names
  (RFC 2606 / 6761 / 6762, `example.*`, `exemple.*`) and XML / schema /
  sitemap namespaces are skipped.
- **links** are every other absolute URL in a string (JSX `href`, content and
  i18n strings, prose): hyperlinks, not dependencies. At most 3 locations per
  host; a host that is already an external is not repeated.
- **infra** is one fact per id + kind: a unit declared again by environment
  overlays (or a Deployment + Service pair) keeps its first location by path;
  `overlays` lists every declaring file when there are several.

Extractor coverage v1 (JS/TS + Python first, the rest listed in README Limits):
routes — Next (app + pages API), Nuxt server, SvelteKit, Remix, Express,
Fastify, Hono, NestJS, FastAPI, Flask, Django urls, tRPC procedures, Next
server actions; calls — fetch, axios, ky, `$fetch`, requests, httpx, tRPC
client hooks / vanilla calls / server callers, server-action invocations and
`action={fn}` forms, with URL normalisation (template params → `:p`,
base-URL prefixes stripped, query dropped) and route matching by method + path
pattern; screens — Next app/pages, Nuxt pages, SvelteKit routes, React Router /
Vue Router literal route tables; entities — Prisma, Drizzle, TypeORM,
Mongoose, Sequelize, SQLAlchemy, Django models, SQL `CREATE TABLE` in
migrations (one entity per table across the migration history, `ALTER TABLE`
columns and foreign keys applied); entityUses — Prisma client calls (`prisma.order.create`), Drizzle
`db.insert(orders)`, ORM model method calls on known entity names, SQL
`INSERT/UPDATE/DELETE/SELECT … <table>` literals; jobs — BullMQ queues/workers,
Celery tasks, `vercel.json` crons, GitHub Actions `schedule`, node-cron;
externals — curated SDK map (stripe, @supabase/*, firebase*, openai,
@anthropic-ai/sdk, @aws-sdk/*, twilio, sendgrid, resend, algolia, sentry,
posthog…) + hosts of URL literals that reach the network (the rest are
`links`) + `process.env.X_*` prefixes; infra — docker-compose services,
Dockerfiles, k8s Deployments/Services, deduplicated across overlays.
Every fact carries `file` + `line`. Routes, calls, screens, entities and jobs
also carry `end`, the last line of their definition (the registering call to
its closing parenthesis, the exported handler, the decorated method, the
model / class / table block; a file-level page spans the file), so a change
can tell which fact a hunk touches. `end` is optional and additive (still
schema 2): a reader of an older facts.json computes it from the file. Each extractor has fixture tests with
true positives AND explicit false-positive guards (comments, strings in tests,
docs).

## 6. view.json (merged view-model, generated)

Produced by `build`/`render` from ultraindex graph + symbols + facts + model +
flows + lenses + timeline + latest change + insights. Shape:

```json
{ "schema": 1, "repo": { "name": "…", "commit": "…", "remote": "https://github.com/o/r", "root": "/abs/path" },
  "nodes": [ { "id": "…", "kind": "cap|sys|mod|file|sym|route|screen|entity|job|ext",
               "label": "…", "parent": "…", "summary": "…", "cites": ["path:line"],
               "metrics": { "loc": 0, "pagerank": 0, "churn": 0, "tests": 0 },
               "caps": ["cap:checkout"], "tags": [],
               "slice": { "of": "mod:src", "system": "sys:database", "qualifier": "@ Database" },
               "links": [ { "host": "cnil.fr", "line": 31 } ],
               "overlays": ["env/dev/db.yaml", "env/prod/db.yaml"] } ],
  "edges": [ { "from": "…", "to": "…", "kind": "import|call|http|rpc|data|event|queue|extends|config", "weight": 1, "derived": true } ],
  "flows": [], "lenses": [], "timeline": [], "changes": null, "insights": [], "glossary": [], "tour": [],
  "coverage": { "filesInSystems": 0.97, "modulesInCapabilities": 0.82 },
  "stale": { "lenses": [], "flows": [], "prose": [] } }
```

- `repo.remote`: `origin` in https form, credentials stripped
  (`git@github.com:o/r.git` → `https://github.com/o/r`); absent without one.
  `repo.root`: the absolute repository path on the machine that built the view,
  **machine-local**, for open-in-editor links only; never written to a
  committed file.
- `metrics.churn`: on a file, the commits touching it within the churn window
  (`CHURN_WINDOW_MONTHS` = 6 months ending at HEAD's committer date, not "now",
  so one commit always gives the same numbers; codeindex `gitChurn`); on a
  module slice, system or capability, the sum of its files' churn
  (file-commit touches). 0 outside git.
- Edge kinds of a matched call: `rpc` when the route it reaches is a tRPC
  procedure or a server action (`route:QUERY|MUTATION|SUBSCRIPTION|ACTION …`),
  `http` for any other route (and for an external reached `via: host`). Both
  roll up like every other kind (module, system, capability).
- `links` (file nodes only): the file's outbound hyperlinks from facts
  `links`, by line then host, deduplicated, at most `LINKS_PER_FILE` = 10.
  Side-panel data: never a node or an edge, so a link to a regulator's site
  never draws as a dependency. `overlays` (infra nodes only): every file
  declaring the unit, sorted, when more than one does.
- `timeline`: every valid line of timeline.jsonl, newest first (by `at`; equal
  times keep the later line first). `changes`: the latest recorded change set
  (highest id under `changes/`), or null. `insights`: `insightsOf`, most
  severe first.

Edge aggregation: file edges roll up to module, system and capability levels
(weight = count), computed at build time so the viewer never aggregates on
the fly for big repos. Symbol-level call edges embedded only for the top N
files by PageRank (default 300 files) — `serve` answers the rest on demand
(`/api/callgraph?sym=`). Size budget: warn when view.json > 15 MB.

### changes / timeline / insights shapes

Exact types: `src/model/types.ts` (`ChangeSet`, `TimelineEntry`, `Insight`).
Every array is sorted as stated; optional fields are absent, never null.

**ChangeSet** (`changes/<id>.json`, and `view.changes`):

| field | type | meaning |
|---|---|---|
| `schema` | `1` | |
| `id` | string | `<YYYYMMDD-HHMMSS>-<short head sha>` (UTC) for committed work, `-worktree` instead of the sha when uncommitted work is included; `-2`, `-3`… on a same-second clash |
| `at` | ISO time | when it was recorded (with `id`, the only time-dependent part) |
| `mode` | `"base" \| "staged" \| "worktree"` | `base`: worktree + commits against the merge-base of `--base` (default origin/HEAD, origin/main, origin/master, main, master); `staged`: the index against HEAD; `worktree`: staged + unstaged + untracked against HEAD |
| `base` | `{ ref, sha }` | the ref asked for and the commit it resolved to |
| `head` | `{ sha?, dirty }` | HEAD; `dirty` when uncommitted changes are part of the set |
| `depth` | number | blast-radius hops (default 2) |
| `counts` | `Record<"cap"\|"sys"\|"mod"\|"file"\|"sym"\|"route"\|"screen"\|"entity"\|"job", { added, changed, removed, impacted }>` | every kind always present |
| `nodes` | `ChangedNode[]`, by id | see below |
| `risk` | `ModuleRisk[]`, score desc then slug | the engine's per-module risk |
| `broken` | `{ from, spec, target, renamedTo?, kind: "import"\|"doc-link" }[]` | imports still pointing at a removed file; `from` / `target` / `renamedTo` are `file:` ids |
| `unindexed` | string[] | changed paths outside the index (not mapped) |
| `notes` | string[] | engine and ultraview notes |
| `fingerprint` | string | sha1 of mode, base sha, head sha and every changed path with status, old path, content hash and hunks: equal = the same change (the hook and `--record` skip it) |

`ChangedNode`: `{ id, kind, label, status: "added"|"changed"|"removed"|"impacted", parent?, at?, changedFiles?, impactedFiles?, linesAdded?, linesDeleted?, hunks?: [start, end][], oldPath?, depth? }`.
`parent` is the view parent (kept so a removed node can be placed); `at`
(`path:line`, base location for a removed fact) on symbols and facts;
`changedFiles` / `impactedFiles` on `cap` / `sys` / `mod`; `linesAdded`,
`linesDeleted`, `hunks` (new-file lines, 1-based inclusive), `oldPath` on
changed files; `depth` on impacted files. A `removed` id may name a node no
longer in `view.nodes`. Classification:

- **file**: git added → `added`; modified or renamed → `changed`; deleted →
  `removed`. `impacted`: the reverse dependency closure of the changed files
  within `depth` hops (codeindex `reverseClosure`, inferred calls skipped, the
  same walk as the engine's risk), plus the importers of a removed file and
  their dependents; never a directly changed file.
- **sym**: exported top-level symbols whose span a hunk touches (a member
  counts for its top-level owner): `added` in an added file, else `changed`.
- **route / screen / entity / job**: the extractors re-run over the base tree
  (unchanged files from disk, changed ones from git at the base commit; skipped
  past 500 changed files, with a note): an id only in the new tree → `added`,
  only in the base → `removed`; in both → `changed` when its definition differs
  (file, handler, fields, schedule…) or a hunk touches the lines it owns (its
  extent `[line, end]`; a hunk of only blank or comment lines owns nothing), else
  `impacted` when its file is changed or impacted.
- **mod / sys / cap**, rolled up from the files under them (a module slice, its
  system, every capability the file serves): `removed` when the node left the
  map, `added` when every file under it is new, `changed` when any file under it
  is added / changed / removed, else `impacted`.

`ModuleRisk`: `{ id: "mod:<slug>", label, path, score, bucket: "high"|"medium"|"low", reasons[], changedFiles[], changedSymbols: { total, exported }, impact: { directFiles, transitiveFiles, modules: mod ids }, tests: { status: "covered"|"gap"|"n/a", files[] } }`
— the engine's delta module (weights in codeindex `RISK_WEIGHTS`), keyed by
the whole module (its slices share it).

**TimelineEntry** (one line of timeline.jsonl, and `view.timeline[]`):
`{ at, source: "agent"|"pr"|"manual", title, request?, summary, items: { ref, change: "new"|"changed"|"removed", note? }[], base?, head?, change?, auto? }`.
`summary` is cited prose (one citation per sentence, every citation
resolving) unless `auto: true` (generated from a change set's counts by
`diff --record` without `--summary`; `check` exempts it). `change` is the id of
the change set the entry records; `base` / `head` are commit shas. A recorded
entry's `items` are its directly changed nodes, symbols aside, capabilities
first then systems, modules, facts, files (at most 100). Each line is one
stable-JSON object (sorted keys, no indentation); the file is append-only and a
line that fails validation is refused, never written.

```json
{"at":"2026-02-03T04:05:06.000Z","auto":true,"base":"a1b2c3d…","change":"20260203-040506-worktree","head":"a1b2c3d…","items":[{"change":"changed","ref":"cap:order-tracking"},{"change":"changed","ref":"cap:ordering"},{"change":"changed","ref":"sys:api"},{"change":"changed","ref":"mod:src-services"},{"change":"changed","ref":"file:src/services/orders.ts"}],"source":"agent","summary":"1 file changed (0 added, 1 changed, 0 removed) and 2 impacted within 2 hops. Capabilities: changed Following orders, Placing an order; impacted Health check. Highest risk: Services (medium, score 45).","title":"1 file changed in Following orders, Placing an order"}
```

**Insight** (`view.insights[]`, `ultraview insights --json`):
`{ id: "<kind>:<key>", kind, severity: "high"|"medium"|"low", title, detail, nodes: view ids, cites: "path:line"[], prompt }`,
at most 10 per kind and 30 overall, most severe first, then by kind in this
order, then by the kind's own score. Built only from engine analyses; the
thresholds are constants in `src/insights.ts`:

| kind | engine source | kept when | severity |
|---|---|---|---|
| `hotspot` | codeindex `rankHotspots` (commits × log2 lines) + `riskHotspots` (complexity) over the churn window | non-test code file, ≥ 5 commits | high ≥ 20, medium ≥ 10 commits |
| `hidden-coupling` | codeindex `changeCoupling { hidden }` over the window | two non-test code files, changed together ≥ 3 times, no edge between them, confidence (Wilson lower bound) ≥ 0.4 | high ≥ 0.7, medium ≥ 0.55 |
| `cycle` | codeindex `checkRules` builtin `cycles` (module import SCCs) | any | high ≥ 4 modules, medium 3, low 2 |
| `dead-code` | codeindex `findDeadCode`, one insight per file | any unused export | high ≥ 5 unreferenced, medium any unreferenced, low only uncalled |
| `untested-hub` | codeindex `untestedModules` | non-test code module with ≥ 3 incoming dependencies | high ≥ 10, medium ≥ 5 |
| `literal` | codeindex `findLiteralDuplications` (engine defaults) | any | competing high, bypassed medium, uncentralized low |

File-level evidence with no line of its own cites line 1. History kinds are
absent outside git.

```json
{ "id": "cycle:src>src-routes>src-services", "kind": "cycle", "severity": "medium",
  "title": "Import cycle: src → src/routes → src/services → src",
  "detail": "3 modules import each other in a loop (src → src/routes → src/services → src): none of them can change or be tested alone.",
  "nodes": ["mod:src", "mod:src-routes", "mod:src-services"],
  "cites": ["src/server.ts:1", "src/routes/orders.ts:1", "src/services/orders.ts:1"],
  "prompt": "Using ultraview and ultraindex, propose a safe refactor to break the import cycle between src, src/routes, src/services (mod:src, mod:src-routes, mod:src-services), citing files." }
```

**The hook.** Claude Code runs `Stop` hooks when the agent finishes a turn.
The hook records **worktree** mode (staged + unstaged + untracked against
HEAD), not `--staged`: an agent edits files and rarely stages them, so a staged
diff would record almost nothing. Each entry therefore shows the whole
uncommitted state after that turn; turns that changed nothing new are skipped
(same fingerprint as the last record), and once the work is committed the next
diff starts again from the new HEAD. Nothing is written into `.git`. In
`--hook` mode the command prints nothing, always exits 0, needs a built index
(it never runs a first build inside a turn), refreshes the map incrementally
when stale and logs any error to `.ultraview/hook.log`.

## 8. Viewer

- One HTML file, offline, data embedded as
  `<script type="application/json" id="ultraview-data">`; when served, it
  subscribes to `/events` and swaps data in place (no page reload, keeps
  camera and selection).
- Tech: TypeScript + Preact (MIT) + elkjs layered layout (EPL-2.0, NOTICE),
  SVG rendering with pan/zoom, layout in a Web Worker, cached per level.
- **Map** with semantic zoom: Business (capabilities + actors + externals +
  entities) → Systems → Modules → Files → Symbols (expand a file in place).
  Double-click drills down; breadcrumb climbs. Edge kinds styled distinctly
  (line style first, colour second: `http` dashed, `rpc` dash-dot in the
  accent colour, "Calls the server (RPC)", `data` dotted, `config` dash-dot
  grey, `event` / `queue` double); hover highlights neighborhood. Parallel
  edges of one pair merge into one line styled by its strongest kind
  (`step` > `rpc` > `http` > `event` > `queue` > `data` > `call` > …).
- **Big repositories** (viewer/lib/groups.ts, levels.ts, hubs.ts):
  - *Folder grouping.* A view of more than `GROUP_LIMIT` = 40 members (the
    hard cap) shows folders instead: members sit in a tree of their paths
    (a module at its directory, a file at its path, a symbol at its file);
    the view starts at their common folder, skips single-child chains, and
    opens the biggest folders in place while it stays within `FILL_TARGET` =
    28 cards. A folder holding more than 40 direct entries is cut into
    balanced parts of at most 28 (`dir~0`, `dir~1`, …). A level with 2–6
    boxes (systems around their modules) groups each box on its own with a
    share of the budget (at least 8). Folder cards carry what they hold by
    kind (modules, files, routes, data models); every member is reachable as
    a card in exactly one leaf view. A "show all" banner draws every member.
  - *Aggregate chips.* Entities, externals and infrastructure joining a view
    collapse into one chip per kind past 2 of that kind (8 at Business),
    lines summed; opening the chip shows them one by one (an entity chip opens
    the Data view), and revealing one of them pins it out of its chip.
  - *Hub summaries.* In every drawn map view, a node receiving lines from
    more than `HUB_SHARE` = 35% of the visible cards, and from at least
    `HUB_MIN_SOURCES` = 6 of them, is a hub: those lines are left out of the
    layout and the per-view line cap, and the hub wears a "used by N" badge
    (N distinct users). Hovering or selecting the hub draws all of them as
    straight connectors; hovering or selecting one user draws its own. The
    legend says "Links to widely used parts are summarized"; the list view
    counts them and tags the hub. Lens, flow and Data views never summarize.
    On egapro (289 modules in one system) this takes the app system's module
    view from 90 drawn lines over 45 cards to 66 over 33, with 33 lines into
    `src/modules` and `src` summarized; its pages folder from 91 to 47.
  - *Line cap.* At most `EDGE_LIMIT` = 150 lines (and at most twice the
    cards, at least 40), each card's strongest first; a banner offers "show
    all links".
  - Same-named cards get the shortest folder tail that tells them apart.
- **No business map yet.** When the agent has not written capabilities, the
  map opens on Systems; the Business level shows what it would hold, the
  prompt that writes `model.json` (copy button) and a way to the Systems map.
- **Data**: ERD of entities with relations; selecting an entity highlights
  the routes/files that read/write it on the map.
- **Flows**: stepper; each step highlights its node and shows the cited note.
- **Lenses**: list of saved questions; opening one shows the answer panel +
  the lens subgraph highlighted on the map; stale lenses greyed with
  "re-ask" (copies the prompt).
- **Changes**: latest change view overlaid (added/changed/impacted colors,
  risk badges), plus the timeline (agent tasks, PRs) — click an entry to
  replay its overlay.
- **Insights**: list with severity; "copy prompt for your agent".
- **Tour**: "Start here" narrated stops.
- Side panel: summary + citations (open in editor: `vscode://file/{abs}:{line}`
  default, configurable `cursor`, `idea`, `zed`, or `{remote}/blob/{commit}/{path}#L{line}`
  when not local), routes, entities, tests, churn, capabilities, what it uses
  and what uses it by edge kind, a file's "Outbound links" (host + line chip;
  never drawn), an infrastructure unit's "Declared in" overlays, "ask your
  agent about this" (copies a prompt naming the node id).
- Cmd/Ctrl-K search across every node kind; with the Ask bridge on, the last
  option is "Ask: <query>".
- Audience toggle: business hides files/symbols and technical labels.
- Deep links: `#view=`, `#level=`, `#focus=`, `#group=` (a folder of a
  grouped view, `dir~n` its part n + 1), `#node=`, `#lens=`, `#flow=` +
  `&step=`, `#change=`. Values are percent-encoded except `:` and `/`, which
  stay readable: `route:ACTION app/actions#save` is written
  `node=route:ACTION%20app/actions%23save`, `mod:src@database` is
  `mod:src%40database`; reading decodes them (and accepts a pasted decoded
  form). Unknown keys and values are ignored.
- **Live** (only when served over http and a `hello` event arrived; a static
  file never shows these):
  - a non-blocking banner under the top bar on `stale` (or a stale
    `hello.stale`): "The code changed since this map was built (N files).
    Run `ultraview build`", with the first changed paths; dismissible until
    the counts change, gone when the index is fresh again;
  - an **Ask box** in the Lenses view header (also on its empty state) when
    `hello.ask` is non-null: it posts `{question}` (≤ 500 characters) to
    `/api/ask` as JSON from the same origin, shows the `ask-progress` stages
    in a polite live region (sending, started, running with the bytes so far,
    validating), and is disabled while any ask runs (`busy`, a 409, or
    another page's progress). On `ask-done` for its own question it waits
    for the lens id to appear in the live data (the `view` event brings it)
    and navigates to `#lens=<id>`; on `ask-error` it shows the error and the
    `lens save` problems. Asks from another page only mark the box busy.
- Light/dark, keyboard navigable, responsive down to phone (list fallback
  for the graph below 600px), WCAG AA contrast.

### 8.1 `serve`: routes, live data and the Ask bridge

Only these routes exist (anything else is 404: no files, no directory
listing). Every response carries `Cache-Control: no-store`,
`X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`,
`X-Frame-Options: DENY`, `Content-Security-Policy: frame-ancestors 'none'`,
and never a CORS header. JSON bodies are compact `JSON.stringify`.

| route | answer |
|---|---|
| `GET /` (`/index.html`) | the viewer page rendered from the current view (`renderHtml`, same bytes as `render` would embed): identical to the static file, plus live updates |
| `GET /view.json` | the current view-model (the bytes of `.ultraview/view.json`) |
| `GET /events` | `text/event-stream` (below); at most 32 streams |
| `GET /api/node?id=<node-id>` | 200: the `show --json` card; 404 `{error, suggestions}`; 400 without `id` |
| `GET /api/search?q=<text>` | 200 `{q, nodes: [{id, kind, label, parent?, at?}] (≤ 25: exact label, prefix, label substring, id substring), modules: [{slug, ids, score, matched, files (≤ 10)}] (ultraindex find, ≤ 8)}`; 400 without `q` |
| `GET /api/callgraph?sym=<id>&depth=1..3&dir=in\|out\|both` | `sym` is `sym:<path>#<name>`, `<path>#<name>` or a bare name; default depth 1, dir both. 200 `{sym, depth, dir, root: [id], nodes: [{id, name, kind, file, line, depth, inView}] (≤ 200), edges: [{from, to, kind: calls\|extends\|implements\|overrides, weight}] (≤ 400), truncated?}` from the codeindex symbol graph (`scanRepo` over the index cache + `buildSymbolGraph` + `neighborhood`, rebuilt when graph.json changes); ids are `sym:` + the codeindex symbol id; 404 unknown symbol; 400 bad depth/dir |
| `POST /api/ask` `{"question": "…"}` | only when the Ask bridge is on (else 404). 202 `{id, question, agent}` (`id` = the lens id it will save under); 400 bad question (empty, > 500 chars); 409 `{error, id}` while another ask runs; 403 cross-origin; 415 not JSON; 413 body > 16 KiB |

Values in query strings are cut to 300 characters.

**Events** (`event: <name>\ndata: <one JSON line>\n\n`; `retry: 3000` first;
a `: ping` comment every 15 s):

| event | data | when |
|---|---|---|
| `hello` | `{version, stale: <stale>, ask: {agent, busy} \| null}` | on connect |
| `view` | `{version, bytes}` | the view changed: the viewer fetches `/view.json` and swaps it in place (`viewer/ui/live.ts`) |
| `stale` | `{index, changed, added, removed, files}` (`files`: first 20) | the index freshness flipped or its counts changed (`runCheck`) |
| `ask-progress` | `{id, question, agent, stage: started\|running\|validating, bytes?}` | the agent started, prints (at most once a second), exited |
| `ask-done` | `{id, question, agent, file, replaced, sources}` | the lens is saved (a `view` event precedes it) |
| `ask-error` | `{id, question, agent, error, problems?}` | the agent failed, timed out, or its answer did not pass `lens save` (`problems` = save's errors) |

**Live data.** `.ultraview/` (model.json, facts.json, timeline.jsonl,
flows/, lenses/, changes/) and `.ultraindex/` are watched; a change
re-assembles the view from the files as they stand (`loadViewInputs` +
`assembleWithNotes`, no re-indexing), debounced 150 ms (a burst is coalesced,
at most ~0.9 s late), writes view.json and pushes `view` only when its bytes
changed. index.html, ask.log, .gitignore, `*.tmp` and our own view.json write
never trigger it. Watchers can drop events (FSEvents just after a watch
starts, network drives), so the names, sizes and mtimes of those files are
also polled every second and a move re-assembles too. Source files are watched (recursively on macOS / Windows;
one watch per indexed directory elsewhere, a 30 s poll beyond 2000
directories) but a change never rebuilds: after 1 s it re-runs ultraindex
`runCheck` and pushes `stale`; `build` (by the agent) refreshes the index,
which the `.ultraindex/` watch picks up. The viewer turns `stale` into its
banner and `ask-*` into the Ask box's progress (§8, viewer/lib/live.ts); it
ignores events it does not know.

**Security.** Binds `127.0.0.1` by default; a non-loopback `--host` is
refused unless passed explicitly, then served with a warning, and `/api/ask`
then only answers loopback clients. Every request's `Host` must name a
loopback host, an IP literal or the bound host (403 otherwise: DNS
rebinding). `POST /api/ask` needs `Content-Type: application/json` (a
cross-origin page cannot send it without a preflight, which is never
granted), and refuses an `Origin` other than `http://<Host>` and a
`Sec-Fetch-Site` other than `same-origin` / `none`. Clean shutdown on SIGINT /
SIGTERM (streams ended, watchers closed, a running agent stopped).

**Ask bridge.** `--ask auto` finds `claude`, then `codex`, on PATH (`none`
turns it off); the executable is spawned by absolute path, cwd = the repo,
the prompt on stdin, a minimal environment (PATH, HOME, locale, temp, proxy,
and the agents' own `ANTHROPIC_*` / `CLAUDE_*` / `OPENAI_*` / `CODEX_*`
variables; nothing else), one ask at a time, 180 s timeout (SIGTERM, then
SIGKILL). The prompt says: run `ultraview lens new "<question>" --id <id>`
(with `--terms "<English code keywords>"` when the question is not in
English), read more if needed, reply with only the lens JSON, write no file. Command lines
(no flag that bypasses permissions, ever):

- `claude -p --output-format text --no-session-persistence --permission-mode dontAsk --tools Bash,Read,Glob,Grep --allowedTools "Bash(node <ultraview.mjs> lens new:*)" … Read Glob Grep --disallowedTools Write Edit NotebookEdit WebFetch WebSearch`
  — `dontAsk` denies whatever is not pre-allowed without prompting; Bash is
  allowed only for ultraview's read-only commands (`lens new`, `lens list`,
  `show`, `dossier`, `status`, `check`).
- `codex exec --sandbox read-only --ephemeral --skip-git-repo-check --color never --cd <repo> --output-last-message <private temp dir>/last-message.txt -`

The reply (Claude: stdout; Codex: the last-message file) is parsed (bare
JSON, a fenced block, or the outermost `{…}`); ultraview forces the proposed
`id` and the asked `question`, drops any `sources`, and runs `saveLens`
(schema, every citation resolves, sources stamped) — never `--force`, so an
ask cannot replace another saved question. Everything the agent prints goes
to `.ultraview/ask.log`.

## 9. Skill (skills/ultraview/SKILL.md) — the loop

1. `status` → route.
2. No map → `build` → read the summary → read only README, manifests,
   entrypoints → write `systems` (cover ≥ 90% code) → for each candidate
   capability `dossier` then write it with citations → `check` until clean →
   1–3 flows + tour → `render` → `serve --open` (or open the file) → report
   in plain words + top insights.
3. A question → `lens new` (`--terms "<English code keywords>"` when it is
   not in English) → read evidence → write lens → `lens save` →
   `check` → point the user at `#lens=<id>` (live if served).
4. After a change / for a PR → `diff --worktree --record --source agent
   --title … --summary …` (one cited timeline entry for the task; `timeline
   add` for a note without a change) → `#view=changes`; `diff --markdown` for
   the PR body; `insights` / `export` when asked.
5. Stale → `build` → `check` → re-ask only stale lenses/flows, re-describe
   only stale capabilities.
6. Big repo (> ~40 modules or > 150 capabilities' worth of evidence) → fan out
   one subagent per capability/system with `dossier` (see references/orchestrate.md).

The skill spells this loop out with its invariants, routing table and
fan-out contract; the shapes, writing rules and viewer are in its
references (`schema.md`, `capabilities.md`, `lenses.md`, `flows.md`,
`change-review.md`, `writing.md`, `orchestrate.md`, `viewer.md`,
`engine-evidence.md`). `render` and `serve` re-assemble the view from what
was saved, so the loop renders without building again. `evals/` measures step 3 (the ranking of `lens new`) and the gates
of steps 2–3 on fixture repos.

Invariants: never read facts.json/view.json/graph.json whole; never write a
sentence without a citation; never hand-copy a detected edge; never delete a
lens or timeline entry; never commit index.html; changes nothing outside
`.ultraview/` except `hook install` (asked explicitly; `.claude/settings.local.json`
unless `--shared`).
